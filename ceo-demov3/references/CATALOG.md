## Textual reference patterns

### USER-ONB-001 — detected Naukri profile card

- **Source:** Inline owner-provided layout; no addressable original bitmap was available during the system reset.
- **Pattern:** Show a detected person, email, dominant Naukri provider CTA, and a concise autofill benefit before Google/Apple alternatives.
- **Constraint:** AmbitionBox and Naukri share a parent company, so the recognised name and email may appear before import. The CEO demo remains deterministic and accesses no real account.
- **Status:** active textual pattern. Add the original asset only if the owner provides an addressable file.

### USER-ONB-002 — Qonto split pitch and login

- **Source:** First shared inline on 2026-08-16; the original bitmap is now preserved as MOB-ONB-008.
- **Pattern:** Give the product pitch a confident coloured world, then use a visibly separate white authentication world with large pill-shaped provider actions.
- **Constraint:** Learn the division and hierarchy, not Qonto's lemon colour, invoice illustration, typography, or account model.
- **Status:** superseded by checksum-backed MOB-ONB-008; retained as conversational history.

### USER-ONB-003 — compact onboarding flow header

- **Source:** Inline owner-provided header crop on 2026-08-16; no addressable filesystem original was included.
- **Pattern:** Back action on the left, six-stage progress centred with an elongated current marker, and a close action on the right. Preserve the structure across screens and let it inherit a blue hero when present.
- **Constraint:** Do not copy the crop's exact colours, proportions, or unexplained navigation behavior. Close remains optional until a safe destination is defined for each screen.
- **Status:** active textual pattern. Add a checksum-backed bitmap if the owner places the original in `references/inbox/`.

### USER-ONB-004 — additive preference controls

- **Source:** Inline owner-provided Naukri Preferences screenshot on 2026-08-17; no addressable filesystem original was included.
- **Pattern:** Keep the high-confidence role, location, and compensation preferences visible, then offer explicit optional additions for companies, tech stacks, role level, work mode, and industries.
- **Constraint:** Learn the progressive-addition model, not the dark theme, Pro upsell, job-search-stage status, exact chip styling, or oversized type and controls. Work mode is already part of the imported AmbitionBox set, so it is not duplicated as an optional field.
- **Status:** active textual pattern. Add a checksum-backed bitmap if the owner places the original in `references/inbox/`.

## Intake rule for future references

1. Check `references/inbox/` first. Move each new original into the relevant `references/<workstream>/<source>/` folder before using it.
2. Give it a stable descriptive filename and unique catalogue ID.
3. Record provenance, SHA-256, relevant layer/screen, learning, non-learning, and status.
4. Do not silently promote prototype, generated, or QA imagery into this catalogue.
5. If the owner rejects a visual direction, preserve the durable reason in `context/FEEDBACK.md`; retain the asset only when it helps prevent repetition.
